# 무림초행 — AI 채팅형 무협 RPG

브라우저에서 자유롭게 행동을 입력하면, 서버의 규칙 엔진이 결과와 상태 변화를 먼저 확정하고 외부 AI는 그 결과만 무협 장면으로 서술합니다. API 키와 비공개 게임 정보는 서버에만 있습니다.

## 구조

```text
브라우저 UI
  → Express 게임 API
  → 규칙 엔진(판정·전투·상태·기억)
  → Groq/OpenAI/Gemini(서술 전용)
  → 브라우저
```

AI가 능력치, 판정 결과, NPC의 비공개 지식이나 과거 사실을 임의로 바꾸지 못하도록 게임 상태와 판정을 코드가 관리합니다. AI 호출이 실패해도 규칙 기반 대체 문장으로 플레이를 이어 갑니다.

## 현재 플레이 범위

- 짧지만 이후 반응이 달라지는 캐릭터 생성
- 직전 결과·단서·경계도에 따라 달라지는 상황별 행동 제안과 자유 입력
- 서버 내부 공개 감사 판정, 화면에는 결과·대가만 표시
- 거리·지형·자세·사기·비살상 선택이 있는 전투
- 단서, 목표, 관계, 세력 반응, 지연 결과 기록
- 행동 본문은 공백 제외 500자 이상: 짧거나 미완결인 AI 응답을 한 번 재작성하고, 실패 시 완결된 장면 서술로 대체
- 시작 인연과 실제로 만난 인물의 관계, 변화 이유와 은혜의 방향 표시
- 목격자·전언 출처·지역·세력을 구분하는 세평과 지연된 소문 전파
- 삼류부터 조화경까지 이어지는 복수 조건 경지와 무공별 빌드 분기
- 별도 무공·성장 UI, 초식·숙련·깨달음·실전·돌파 조건 추적
- 반복 행동과 정체 신호를 감지하는 피로도 제어
- 첫 지역에서 이어지는 3개 장면의 플레이 가능한 수직 단면

전체 캠페인 설계와 구현 규칙은 [게임 설계 문서](docs/GAME_DESIGN.md)에 있습니다.

## 설치 및 실행

Node.js 18 이상이 필요합니다.

```bash
npm install
copy .env.example .env
npm start
```

`.env`에 사용할 제공사의 키를 설정합니다. 기본 제공사는 Groq입니다.

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=발급받은_키
```

브라우저에서 <http://localhost:3000>을 열어 인물을 만든 뒤 바로 플레이할 수 있습니다. `.env`는 `.gitignore`에 포함되어 GitHub에 올라가지 않습니다.

## 다른 AI 제공사

실제 키는 로컬 `.env` 또는 배포 환경의 비밀 환경 변수에만 저장합니다. `.env.example`의 키 값은 반드시 비워 둡니다. 키가 GitHub에 올라갔다면 파일 삭제만으로 해결되지 않으므로, 제공사 콘솔에서 기존 키를 폐기하고 새 키로 교체해야 합니다. 브라우저 코드, 채팅, 로그에는 키를 넣지 마세요.

## 서술과 인연·세평

서술은 정통 무협소설의 3인칭 장면을 목표로 합니다. 본문은 900~1,400자, 5~8개 문단을 요청하고 공백 제외 500자 이상인지 서버에서 검사합니다. 토큰 예산은 처음 3,200, 재작성 4,800이며, `AI_MAX_TOKENS`는 기존 단순 채팅의 기본값입니다. 세 제공사의 미완료 종료 신호, 문단 끝, 열린 따옴표를 검사하고 미완성 본문은 노출하지 않습니다. 재작성은 서술만 다시 호출하므로 행동 비용과 판정은 중복 적용하지 않습니다. 통신 실패 시 추가 호출 없이 장면·행동·결과에 맞는 대체 서술을 반환합니다.

시작 인연은 선택한 배경으로 표시하고, 현장에서 만난 인물의 관계와 구분합니다. 인연 카드에는 관계 설명과 최근 변화의 이유가 나오며, 상세 기록에서 신뢰·호의·두려움·이해관계를 확인할 수 있습니다. 은혜는 누가 누구에게 갚아야 하는지 문장으로 표시합니다. 높은 두려움이 곧 적대 관계를 의미하지는 않습니다.

세평은 확인된 사건과 소식이 도달한 범위에만 생깁니다. 부상 치료는 당사자, 인부 구조는 현장 목격자에게 먼저 알려지고, 후속 증언 이후 백로진 일대로 전해집니다. 증거를 공유하면 실제로 받은 세력에만 협력의 평판을 남깁니다. 같은 구조·치료 보상은 중복 적용하지 않으며, 이미 구조된 인부를 방치했다는 악평도 만들지 않습니다. 본문 속 모든 사실을 의미 단위로 검증하는 기능과 전체 강호의 소문 전파망은 아직 없습니다.

## 제공사 전환

```dotenv
# OpenAI
AI_PROVIDER=openai
OPENAI_API_KEY=발급받은_키

# 또는 Gemini
AI_PROVIDER=gemini
GEMINI_API_KEY=발급받은_키
```

`AI_PROVIDER`만 바꾸면 같은 게임 엔진을 유지한 채 서술 AI를 교체할 수 있습니다. 모델은 `GROQ_MODEL`, `OPENAI_MODEL`, `GEMINI_MODEL`로 지정합니다.

## 게임 API

- `GET /api/health`: 서버 상태
- `GET /api/game/options`: 캐릭터 생성 선택지
- `POST /api/game/start`: 새 세션 생성
- `GET /api/game/state/:sessionId`: 공개 상태 조회
- `POST /api/game/action`: 선택지 또는 자유 행동 처리
- `POST /api/chat`: 기존 단순 AI 채팅 호환 경로

새 게임 예시:

```bash
curl -X POST http://localhost:3000/api/game/start \
  -H "Content-Type: application/json" \
  -d '{"character":{"name":"연우","origin":"border_refugee","past":"failed_rescue","talent":"keen_eye","tenet":"no_kill","bond":"herbalist_debt","martialPath":"flowing_sword","longGoal":"protect_route"}}'
```

응답의 `sessionId`로 행동합니다.

```bash
curl -X POST http://localhost:3000/api/game/action \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"발급된_ID","message":"수레바퀴 자국과 뱃사공들의 표정을 살핀다"}'
```

## 테스트

```bash
npm test
```

테스트는 게임 판정, 실패 후 진행, 반복 감지, 장면 전환, API 오류 처리와 공급사 응답 변환을 실제 과금 없이 검증합니다.

## 현재 제한

세션은 서버 메모리에 저장되므로 서버를 다시 시작하면 사라집니다. 첫 재미 검증 단계에서는 DB를 두지 않았습니다. 장기 캠페인으로 확장할 때 설계 문서의 상태 JSON을 파일 또는 DB에 저장하는 계층을 추가하면 됩니다.
